Where the last module left you

You have a table now, with eight columns and one row for every file, and a client who has already told you which rows are keep, fix, and retire.

That table is already worth the fee you charged for it. This module makes it do a second job entirely, which is telling both you and the machine what the website is actually going to be.

Four more columns do that.

ReadyYes, or the one thing still missing

Now the sheet is not merely a list of files, because it has quietly become a build plan that anybody at all can read. That includes you at seven in the morning, a helper you hire next year, and a chat window.

Three ways to build the list

You have three routes, and the right one depends entirely on how many files there are.

By hand. Open the folder and type the rows. Under about 150 files this is genuinely the fastest available option, and you should not feel especially clever for avoiding it. You also see every file while you type, which is worth considerably more than it sounds.

A Drive add-on. Drive Explorer is the one most people land on, it has over a million users, and it writes file details straight into a Sheet with no code at all. The free tier caps each export at roughly 200 items, so a real business Drive will need either the paid version or several separate passes.

A script. Google Apps Script is free, runs inside the client's own account, and needs no billing arrangement of any kind.

Be careful how you sell that last one.

Apps Script is not "no code"

People describe Apps Script as a no-code tool because you never install anything, but you still have to paste in a program, and when it breaks you still have to read an error message.

There is a harder limit as well, because a single run stops automatically after six minutes, which means a large Drive will time out partway through. Getting round that means writing the job so that it resumes exactly where it stopped, and that is programming by any honest definition.

What the Drive API actually gives you

If you go the script or API route, there is one mistake that catches nearly everybody the first time.

Ask Drive for a list of files and give it no further instructions, and it hands back almost nothing useful at all, which is an identity, a name, a type, and very little else.

The remedy is a setting called fields, where you name every single column you want, and if you miss it your beautiful spreadsheet arrives almost completely empty.

These are the ones worth asking for.

The size column will be mostly blank

Drive only reports a size for files that hold binary content, meaning photographs, recordings, and documents of the ordinary downloadable kind.

Google Docs, Sheets, Slides, folders and shortcuts all come back with nothing whatsoever. If you promise a client a report on what is eating their storage, most of the rows will arrive empty and you will look careless when you meant to be helpful.

There is also a search language available, so you can ask narrower questions before you ever open the sheet, filtering on name, type, owner, folder, starred, trashed, and dates. You can also search inside the contents of the documents themselves, which is easily the fastest way to find every file still carrying an old telephone number.

Writing labels back onto the files

A spreadsheet catalogue goes stale, exactly as the previous module warned you. One reliable way to slow that decay is to write the label onto the file itself rather than only into your sheet.

Drive gives you two places to put custom labels, and both come with real limits.

Description is the note field in the Drive details pane, which a human can read and edit without any tools whatsoever, so this is where anything the client genuinely needs to see should go.

Properties are hidden pairs of keys and values that only software can read or write. They are useful for a status code or a category tag, and they are useless for anything resembling a sentence.

The limits are tighter than they look

A file can carry at most 100 custom properties, and no single property may exceed 124 characters, counting the key and the value together.

So a ten-character key leaves you 114 remaining characters, which holds a status, a date, or a client code comfortably. It does not hold a sentence and it certainly does not hold a summary.

There is also no screen for these properties anywhere in Drive, so the client will never see them, which means the client can never correct them either.

The practical rule is mercifully short: put machine labels in properties, put anything a person must read in the description, and keep your sheet as the working copy.

Getting it into the Sheet

Sheets can be written to by software, and the method you want appends new rows onto the end of a table.

The limits are generous for this kind of work, since a project may make 300 read and 300 write calls a minute, while a single user inside that project may make 60 of each. Going over the limit returns an error rather than a charge.

One thing to watch, and you should say it out loud to a client who is nervous about bills.

Free today, with a stated expiry

Google's own documentation says that standard use of the Sheets service costs nothing extra, and then says that going over the limits is planned to incur charges later in 2026.

So the honest line is "free within the limits, and Google has announced paid overages this year." Do not say "the API is free" and leave it there.

Now the hard part

Here is the question the client actually asked. The sheet is built, the rows are clean, so does the website now build itself?

Half of it does. The half that does is not the half most people expect, and you need to know this before you promise anything.

Google Sites cannot be written to

There is no way for software to create a page in Google Sites, add a paragraph, or place an image. None. Not at any price and not on any plan.

The old Sites service was shut down for scripts on 24 September 2024. The remaining developer service is marked deprecated and, in Google's own words, cannot reach the version of Sites that launched in November 2016. That is the version absolutely everybody uses.

A search result that will mislead you

Search for a Sites API and one of the first results you will find is a Google announcement that reads exactly like current news. It is dated January 2010 and describes a product that no longer exists.

Somebody on your team will find that page, tell you this is solved, and lose two days. Warn them first.

What software can do is treat the whole site as a single file, so it can find it, rename it, move it, share it, and put it in the bin. It simply cannot open the thing up and write inside it.

So the real mechanism is a person sitting in the Sites editor, inserting the Sheet and the charts and the images.

That sounds like a defeat, and it is not, for two separate reasons.

The first is the part almost nobody notices. When you embed a published Sheet into a Google site, the site carries on reading from that Sheet, so changing a price in the spreadsheet changes the page. Google says the update "might take a few minutes". The build is manual, but the data stays alive afterwards without anybody touching it.

The second reason is bigger, and it is what the next module is about.

A missing API is not the same as a missing door. The editor is a web page. A web page can be driven. If nobody will give you a way in through the back, you can walk something through the front the same way a person does, clicking and typing, working straight down your catalogue.

That is not a trick and it is not a workaround you should be embarrassed by. It is you building the interface the vendor declined to build, which is an ordinary and respectable thing to do. It has real rules, real limits, and one line you must not cross, and Module 27 covers all three.

ChatGPT Sites is real, and it has the opposite problem

This one surprised me, so I checked it four ways. It exists, it is a first-party product, and it went into public beta on 9 July 2026.

It builds and hosts a real site from a conversation, with proper deploy links, storage behind it, and custom domains where they are offered. As a way of turning a plan into a working page, it is genuinely impressive.

Three things about it will bite a client, so check all three before you promise anything.

It is not on the free plans. Paid tiers only, and the exact list has moved more than once since launch.

Public publishing is restricted by country. At launch it was not available for public sites in the United Kingdom, the European Economic Area, or Switzerland. If your client sits in one of those, ask before you sell.

It cannot read live data. This is the important one. The documentation is blunt about it: the tool cannot connect to a live source today, and the recommended approach is to gather updates separately, review them, and refresh the site by hand.

There is also no way for software to trigger a publish, so a person prompts it, a person reviews it, and a person presses deploy.

The inversion worth teaching

Put the two side by side and the result is backwards from what anybody expects.

Google SitesChatGPT Sites
Building the pagesNo automation at allStrong automation
Keeping the data currentLive, through the embedManual refresh, every time
Software can publish itNoNo

A beginner assumes the newer tool wins on both counts. It does not. It wins the build and loses the upkeep.

For a client whose content barely moves, such as a story, a service list, or a set of photos, the newer tool is the better buy. For a client whose numbers change weekly, such as prices, stock, or hours, the older one is quietly stronger.

So is the cataloguing step really the same either way

Yes, and the last module's claim survives the test. Everything up to the finished sheet is identical whichever platform you end up on.

But be honest with yourself about why.

The step is shared because neither platform can read your sheet on its own, which means it is equally disconnected from both of them. That is not evidence of a well-designed foundation, and it is worth saying plainly, so that nobody on your team wastes a fortnight hunting for an integration that does not exist.

The catalogue still earns its money, and here is the reason it does. The human step that follows takes a single afternoon when the list exists, and it never happens at all when the list does not. The client with nine years of files does not stall because the tools are weak. She stalls because she cannot answer a basic question about her own material.

The row that says "not through an API" is the interesting one, and it is where the next module goes to work.

What you actually do on Monday

  1. Add the four build columns to the sheet you made last module, and fill in Page and Order for the keep rows only.
  2. Pick your route by size. Under 150 files, type it. Over that, try the add-on before you reach for a script.
  3. Ask for the fields you want by name, and expect the size column to be mostly empty.
  4. Choose the platform from the upkeep, not the build. Ask one question: how often does this content change? Weekly means Google Sites and a live embed. Rarely means the newer tool and a faster build.
  5. Book the refresh now. Put a date in the calendar to run the list again, because the sheet is a photograph and photographs age.

That last step is the one that turns a one-off job into a care plan, and the care plan is where this business actually makes its money.

Two modules left in this part. The catalogue is built and the platform is chosen, so the questions still open are how the rows get onto the pages without you typing every one of them, and how the whole thing stays true after launch.

Check yourself

Three questions, no score, nothing recorded. Answer each one in your head first, then reveal. Trying to recall something is what moves it into memory — rereading does not, which is why reading it again feels productive and is not.

1. You ask Drive for a list of files and the spreadsheet comes back nearly empty. What went wrong?

You did not name the fields you wanted. Given no instructions, Drive returns only an identity, a name and a type. You have to list every column you want by name, and that one omission catches almost everybody the first time.

2. Can software build a page in Google Sites? What does that mean for the job?

No, not at any price and not on any plan. The old service was shut down for scripts in September 2024 and the remaining one cannot reach the current version of Sites. A person builds the pages, and software can only find, rename, move or share the site as a whole.

3. Google Sites and ChatGPT Sites each win one half of this job. Which half does each one win?

ChatGPT Sites wins the build, because it can generate a working site from a conversation. Google Sites wins the upkeep, because an embedded Sheet keeps feeding the page after launch. Choose by how often the content changes, not by which tool sounds newer.
